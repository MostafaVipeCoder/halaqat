# توثيق الخصائص الموحّد — منصة SaaS لإدارة مدارس تحفيظ القرآن

الوثيقة دي بتجمع كل الخصائص الموجودة في المشاريع الأربعة (A, B, C, D) في قائمة واحدة **من غير تكرار**، ومرتبة بشكل يخدم بناء منصة SaaS واحدة لمدارس التحفيظ.

## مفتاح القراءة

**المصدر**
- **A** = `react-figma-versions/v7-schools-supabase` (والنسخ الأقدم v1–v6 لو الميزة موجودة فيها بس)
- **B** = `quran-schools-manager-react`
- **C** = `quran-schools-management-vue`
- **D** = `quran-schools-saas-trpc`

**الحالة**
- ✅ متنفذة وشغالة على قاعدة بيانات حقيقية
- 🟡 واجهة / بيانات وهمية (mock) — الفكرة والتصميم جاهزين
- 📐 موجودة في تصميم الداتابيز أو الأنواع (types) بس
- 🆕 مش موجودة في أي مشروع — **مقترحة** لأنها أساسية لمدرسة تحفيظ

> **أهم ملاحظة:** ولا مشروع من الأربعة فيه متابعة حفظ القرآن نفسه (سور، أجزاء، صفحات، تسميع، مراجعة، تقييم تجويد). المشاريع كلها "إدارة مدرسة عامة". عشان كده القسم 5 (🆕) هو قلب المنصة ولازم يتبني من الصفر.

## 4. الطلاب

### 4.1 بيانات الطالب (السكيمة الموحّدة المقترحة)
مجمّعة من A + B + C + D:
- **أساسي:** رقم الطالب التلقائي (`STD-YYYY-####`)، الاسم، الرقم القومي، تاريخ الميلاد، النوع، الصورة، الموبايل، الإيميل، العنوان
- **ولي الأمر:** الاسم، صلة القرابة، الموبايل، الإيميل

- **مالي:** خطة الدفع (شهري/فصلي/سنوي)، المبلغ، حالة الدفع، **معفي من الرسوم**
- **الحالة:** نشط / موقوف / مفصول / متخرج
- **QR:** كود فريد + slug لرابط الملف

## 11. التوصية التقنية لبناء المنصة الموحّدة

1. **الأساس:** ابدأ من **A (v7)** — React + Supabase + React Query. هو الوحيد الشغال فعليًا وفيه RLS بـ `school_id` ولوحة سوبر أدمن.
2. **الداتابيز:** خد من **C** جداول `school_members` و`subscriptions` و`notifications` و`audit_logs` وأعمدة الطالب الموسعة، وصحّح فيها: إضافة سياسات RLS (C مفعّل RLS بدون سياسات)، وتفعيل `pgcrypto`.
3. **الواجهات:** انقل من **B** تصميم صفحات الباقات والاستهلاك، طاقم العمل وكود الماسح، خطط الدفع، الاستيراد من Excel، والتقارير المجدولة — وربطها بالبيانات الحقيقية.
4. **ابنِ جديد:** القسم 5 (الحفظ والتسميع)، بوابة ولي الأمر، تكامل الواتساب، تطبيق الأدوار فعليًا، تطبيق حدود الباقات والإيقاف ووضع الصيانة، والـ Onboarding.
5. **استبعد:** D كأساس (OAuth خاص بـ Manus + MySQL + ثغرات IDOR في بعض الـ procedures)، لكن ممكن تستفيد من فكرة جدول `subscription_plans` بأعلامه (whatsappIntegration, advancedReports, apiAccess).

### مشاكل لازم تتصلح في A قبل البناء عليه
- السكيمة الحقيقية موجودة في مشروع Supabase مش في الريبو (جداول `profiles`, `school_settings`, `subscription_packages`, `suspensions`... مش متعرفة في SQL) → تصدير السكيمة كـ migrations.
- الخدمات بتدخل `user_id` بس مش `school_id` رغم إن الـ migration بيخليه NOT NULL.
- `school_settings` بيتقرا بـ `user_id` بدل `school_id`.
- نسيت كلمة السر و تصدير PDF/CSV وتحميل الفاتورة كلها وهمية.
- كود ميت: `useAuth.tsx`، `staffService`، `payrollService`، `GradesTab`، `StudentActionModals`.
